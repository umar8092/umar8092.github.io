Microsoft, Google and Meta app verification

Enterprise customers won't connect an app that shows an unverified warning. I worked directly in Microsoft, Google and Meta's developer consoles to set up, verify and keep enterprise-critical connectors approved.

How it works

Microsoft Azure / Entra ID

  1. App registration: in Entra ID
  2. Permissions: Microsoft Graph scopes, redirect URIs
  3. Domain verification: publisher domain
  4. Verified app: trusted by enterprise tenants

Google

  1. OAuth consent screen: app details and branding
  2. Scope selection: justifying each sensitive scope
  3. Scope verification: Google's review
  4. Verified app: no unverified-app warning

Meta

  1. App setup: in Meta for Developers
  2. Permissions: requesting the scopes the use case needs
  3. App Review: submission and approval
  4. Live app: approved scopes in production

What I built

  • Microsoft: app registrations in Entra ID, Graph API permissions, and domain verification
  • Google: OAuth consent screen setup, scope justification and scope verification
  • Meta: app configuration, permission requests and App Review
  • Kept connectors approved and working as each platform changed its APIs and policies

Stack

  • Azure

  • Microsoft Graph
  • Google OAuth
  • Meta App Review
  • OAuth 2.0
